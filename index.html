Version Control System

Apa itu Version Control System (VCS)?

Version Control System (VCS) adalah sistem untuk mengelola perubahan pada dokumen atau kode dari waktu ke waktu. Karena perubahan direkam, kita dapat kembali ke versi sebelumnya, melacak siapa yang melakukan perubahan, dan bekerja kolaboratif tanpa saling menimpa pekerjaan.

Tipe VCS

  • Local VCS — metode sederhana seperti menyalin folder rawan kesalahan.
  • Centralized VCS — satu server pusat menyimpan seluruh versi (kekurangan: single point of failure).
  • Distributed VCS (DVCS) — setiap klien mengkloning seluruh repositori (riwayat lengkap), sehingga setiap klon merupakan cadangan penuh.

Git

Git adalah DVCS yang banyak dipakai untuk mengontrol versi source code. Ada tiga keadaan utama file di Git:

  1. modified — file berubah tetapi belum dipersiapkan untuk commit;
  2. staging — file telah ditandai (git add) untuk dicatat pada commit berikutnya;
  3. committed — perubahan telah tersimpan di database lokal.

Perintah dasar Git 

git init                    # inisialisasi repository lokal
git add .                   # tambahkan perubahan ke staging area
git commit -m ""            # simpan snapshot ke history lokal
git branch -a               # lihat branch
git checkout                # buat & pindah ke branch baru
git merge                   # gabungkan branch
git remote -v               # memeriksa repositori jarak jauh yang terhubung 
git push                    # kirim ke remote
git pull                    # ambil & gabungkan dari remote
git fetch                   # ambil update tanpa merge otomatis

GitHub — platform kolaborasi

GitHub mempermudah kolaborasi: hosting repo, kontrol akses, issue tracking, PR (pull request), CI/CD, dan wiki. Alur kontribusi umum (jika tidak memiliki akses push langsung): Fork → Clone → Buat branch → Edit → Push ke fork → Buat Pull Request ke repo asli.

Fork, upstream, dan Pull Request (alur)

  1. Fork repo asli ke akun GitHub kamu.
  2. Clone fork ke lokal (`git clone `).
  3. Tambahkan remote upstream (`git remote add upstream `) untuk sinkronisasi.
  4. Buat branch baru untuk perubahan (`git checkout -b nama-branch`).
  5. Edit file (mis. `index.html`), commit, push ke fork (`git push origin nama-branch`).
  6. Buka fork di GitHub → klik "Compare & pull request" → isi judul & deskripsi → Create pull request.

GitHub Pages (publikasi halaman)

GitHub Pages memungkinkan mempublikasikan halaman web langsung dari repo. Langkah aktivasi: Settings → Pages → Source: Branch main (root) → Save. Biasanya beberapa menit kemudian muncul link `https:// .github.io//`.

Dokumen dan ringkasan diambil dari modul pembelajaran Version Control System.
